# 全应用性能与数据界面分离

用户要求外观、空间管理等页面流畅，并将颜色输入改为可视化选色。沿用自主完成授权；全部本机验证保持无窗口、无鼠标键盘及剪贴板操作，不批量删除任何文件。

## 方案

采用后台生成只读展示数据、界面按可见区域绘制、稳定视图缓存的组合。只缓存字符串/颜色不足以消除布局成本；整体更换 UI 框架会引入无关迁移，暂不采用。

- 数据层负责统计、过滤索引、格式化结果和磁盘检查；界面不得在 render 中访问文件系统。报告按资料库及数据版本区分，不能把旧报告套到新资料库。
- 外观保留同一份设置草稿，按区域虚拟化，并通过明确的输入值、主题、字号、忙碌状态、当前预设和分类版本失效缓存。滚出屏幕的焦点输入仍能接收按键。
- 空间管理在后台扫描结束时生成不可变展示报告；清理列表只布局可见行。动态草稿锁独立维护，不能随报告固化。删除前依然检查权威状态，外部跟踪文件永不删除。
- 今日、复习、统计、笔记库分别审计派生数据和列表规模。已有版本索引/历史虚拟化保留；将重复统计和排序移到独立只读模型，按数据变化更新。
- 可视化选色通过可复用组件提供色盘和色相/饱和度/亮度控制，固定不透明；保留精确 #RRGGBB 与 Markdown 自动适配。颜色草稿解析/校验独立于 GPUI；打开或关闭选色器不改变设置，保存才持久化。

## 验证

使用无界面规模/失效/滚动锚点/离屏焦点测试；GitHub Windows CI 运行同一构建下的 eager/virtual 对照及普通缓存绘制，区分强制重绘与正常通知。发布流程另测优化构建。耗时明确标注测量边界，不把构建行数或缓存命中冒充端到端帧率。

参考 [GPUI Kit 视图缓存](https://gpui-kit.com/docs/view-cache/) 与 [Apple 的性能分析指导](https://developer.apple.com/documentation/Xcode/understanding-and-improving-swiftui-performance)。具体 API 以仓库锁定的 GPUI 0.3.9 / GPUI Kit 0.7.3 源码验证。
