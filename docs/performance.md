# 数据与界面的性能边界

设置、空间管理和统计的优化以重复工作的实际来源为依据。磁盘、网络、统计汇总和历史索引不在 `Render` 中执行；界面读取当前资料库对应的展示模型，用户操作仍提交给原有后台服务。

## 页面与数据来源

| 区域 | 数据层 | 界面职责与失效条件 |
| --- | --- | --- |
| 今日、统计 | `read_models.rs` 在 worker 生成 91 天统计、日期/状态索引、累计时间 | 读取索引；计时显示使用当前时间。日界线、时区、记录/复习事件和资料库变化时重建 |
| 复习 | 同一模型保存稳定排序、到期时间、今天完成的 ID | 到期数量用二分边界；勾选/撤销仍交给核心命令 |
| 笔记库 | 后台 `LibraryIndex`，目录搜索/排序/折叠的结果缓存 | 展开状态属于界面；相同索引的定时快照不重建目录数据 |
| 阅读与历史 | 当前快照的笔记/版本索引、已有 diff 缓存、持久 WebView 编辑器 | 选中文档变化时加载正文；其他页面仅隐藏编辑器，不扫描历史 |
| 草稿 | `draft_viewmodel.rs` 记录身份、版本、标题、排序和匹配结果 | 空查询不读正文；修改查询或草稿版本后才搜索，不保留额外小写全文副本 |
| 设置 | 独立设置草稿、快捷键校验缓存、外观实体 | 快捷键和外观只布局可见项；父页面通知可复用外观缓存，字段/主题/尺寸变化正常失效 |
| 选色 | `ColorDraft` 解析规则，原 `InputState` 保存未提交设置 | 色块和输入框共享草稿；首次打开才创建 picker，后续复用；关闭、悬停不保存配置 |
| 空间管理 | 原有后台扫描加 `StoragePresentation`；展示数据包含已格式化文本和身份索引 | 可见行列表；新报告、路径显隐、字体/间距、草稿保护状态改变时重新测量并保留位置 |
| 同步、图片、更新 | 既有后台同步、资源处理和下载/安装服务 | 界面只消费状态和进度；本次不新增渲染中的磁盘/网络操作 |
| 通知、窗口/分栏 | 独立通知实体和既有布局状态 | 位移与尺寸变化分开；分栏拖动只提交最终尺寸；不把定时通知当成内容变化 |

快照和 `Arc<SnapshotReadModels>` 必须成对交付，包括延迟切换资料库。索引位置只对对应快照有效。版本集合以 `Arc` 身份检测变化；旧模型保留旧集合，不能被后续原地覆盖。跨天计算沿用本地日界线，测试包括夏令时的 23/25 小时日期。

空间报告不能授权删除。确认时重新检查当前资料库、后台忙碌状态及完整草稿目录，包括未完成保存的目标笔记；后台继续验证归属和路径，只清理单个明确的托管副本。外部跟踪文件不能由空间管理删除。

## 验证方法

- 本机只运行低优先级、受限并发的控制台与 GPUI 无界面测试，不启动应用、不操作鼠标键盘、焦点或剪贴板。
- 数据回归覆盖缓存复用、跨天/时区、排序/撤销、版本替换、资料库切换、草稿搜索和存储身份变化。
- GPUI 无界面回归覆盖可见行构建数量、嵌套滚轮边界、变高列表范围、离屏焦点和缓存后更新。
- GitHub Windows runner 独立运行设置交互、选色、存储性能以及完整原生场景，保留截图和 JSON 数据。
- 性能对照复用同一二进制的实际行构建器，比较全部构造与可见行构造；只在 `ui-test` 中提供对照路径。强制 `render_frame` 会绕过视图缓存，普通父通知缓存测量单独记录。
- 时间测量包含 GPUI 事件分发/布局/绘制调用，不包含系统输入传输、合成器呈现；不换算成端到端帧率承诺。完整展开的笔记树、复习卡片和历史时间线尚未全部虚拟化，数据索引测试不能替代这些布局的规模测试。

最近测试结果与原生 CI 边界见 [验证记录](verification.md)。
