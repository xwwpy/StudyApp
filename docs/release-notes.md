# WW-StudyApp 0.5.0 · 笔记拖放、快捷菜单与显示设置

笔记分类可直接通过拖放或右键菜单完成，文件路径按需显示，目录操作和空间管理列表更适合键盘与滚轮使用。

- 将笔记列表中的笔记拖到目录或「未分类」，有效目标会在悬停时突出显示。移动只改变分类元数据，源文件和版本历史保持原样。
- 右键笔记可「移动到目录」「在文件资源管理器中显示」或「复制文件路径」。移动菜单可滚动，列出完整目录路径和适用的「未分类」，排除笔记当前目录；原有移动按钮使用相同规则。
- 移动目录排除当前上级、自身、子孙目录和超出八层深度限制的位置。旧资料库的过期拖放和菜单动作会被拒绝，维护期间不能移动。已取消管理的笔记仍可调整分类。
- 新建和重命名目录时按 Enter 提交，保留名称校验与忙碌状态限制；连续 Enter 不会重复创建。
- 「显示文件路径」默认关闭，包括从旧设置升级的资料库。开启后在笔记列表、详情、编辑区和空间管理中显示位置，保存后重启仍保留选择。右键显示原文件、复制路径始终可用。
- 空间管理中的托管副本列表独立滚动，到达顶部或底部也不会带动设置页；列表外的滚轮继续控制设置页。
- 产品显示名称改为 **WW-StudyApp**，便携包为 `WW-StudyApp-0.5.0-windows-x86_64.zip`，解压后运行 `WW-StudyApp.exe`。现有资料库、配置、同步目录和凭据标识继续沿用，开发构建仍使用 `studyapp.exe`。

修复 Windows 绘制层遮住 WebView2 导致的笔记空白、无法查看和编辑问题。首次打开、历史与页面切换、右键菜单关闭及窗口缩放后，均使用实际桌面像素验证正文可见，并通过真实键盘输入确认编辑和关闭前草稿落盘。侧栏悬停信息放在编辑窗口之外，学习日期、上次复习和下次复习时间可正常查看。

修复 Emoji 被系统分成两次 UTF-16 输入时可能导致编辑冻结的问题。不完整字符保存失败会给出提示并恢复编辑；有效正文保留。大量累计修改分批同步，保留未修改内容的混合换行，并逐批遵守 4096 个补丁和 10 MiB 限制。

Windows 10/11 x64，使用 GPUI Kit 0.7.3 外壳和本地 WebView2 编辑面。需 Microsoft Edge WebView2 Runtime；资源随程序离线打包，无需 Node.js。连续 Markdown 编辑、源码切换、语法高亮、版本历史及草稿机制沿用现有文档协议。Windows 绘制层使用随源码维护的小型 GPUI 补丁，发布包包含完整修改源码、许可证及来源说明。

沿用 schema 3，兼容读取旧 schema 1/2。默认数据库位置仍为 `%APPDATA%\StudyApp\StudyApp\data\studyapp.sqlite3`，升级前可先导出备份。目录移动不删除文件；空间管理仍只允许逐份确认清理托管副本，历史和学习记录保留。

同步只传输最新 Markdown，学习记录、复习计划及完整历史仍在本地；微信和账户级云端仍为预留接口。ZIP 未代码签名，无自动更新器。实际验证和限制见 [验证记录](https://github.com/xwwpy/StudyApp/blob/main/docs/verification.md)。
