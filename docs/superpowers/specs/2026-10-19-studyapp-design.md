# StudyApp 本地首版设计（已确认）

日期：2026-10-19

用户已于同日确认继续，并授权后续直接实现、验证和提交，无需再次人工审核。

## 范围与选择

用户要求使用 gpui-kit 实现学习桌面应用，导入 Markdown 笔记、定时询问学习内容、管理复习、展示统计、查看文件历史，并将代码提交至 https://github.com/xwwpy/StudyApp，配置 CI/CD。

用户补充需要微信登录与本地、云端、双端保存；随后明确选择「先完成本地功能，保留云端和微信接入」。因此本次交付以无需登录即可完整使用的 Windows 本地版为验收目标。云端同步与真实微信授权不计作已完成能力。

比较过的实现方向：

1. 推荐：原生 gpui-kit + SQLite，业务规则独立于界面，预留认证和同步边界。本地可用、不依赖服务器，后续扩展需要实现后端协议。
2. 立即实现桌面与云后端：可一次覆盖账户和同步，但依赖域名、部署环境、微信开放平台配置，与用户已选择的首版范围不符。
3. Markdown 文件与 JSON 配置直接保存全部数据：初期简单，但历史查询、事务、统计和同步冲突处理较复杂，不采用。

## 平台与技术

- Windows 10/11 x64 原生桌面应用，中文界面，使用 gpui-kit 0.7.3。
- Rust workspace：核心业务与数据库库、GPUI 桌面程序两个边界。核心业务测试无需启动图形窗口。
- SQLite 保存业务数据和 Markdown 快照，数据库迁移版本化，写操作使用事务。
- 时间内部保存为 UTC；页面按用户所在本地时区显示，统计按本地自然日分组。
- 文件监听与快照计算在后台执行，界面显示扫描、成功、错误状态。
- 数据目录默认位于用户应用数据目录，允许选择本地资料库目录。
- 不将用户笔记、数据库、令牌、个人路径及开发密钥提交到代码仓库。

## 页面与交互

左侧导航：今日学习、笔记库、复习计划、学习统计、设置。

- 今日学习：本次计时、下一次询问倒计时、当前待回答卡片、今日学习记录、今日待复习数量。
- 笔记库：导入按钮、搜索、笔记列表、Markdown 阅读区、版本历史及差异视图。
- 复习计划：待复习、逾期、今天已完成列表，复习条目可勾选完成；支持撤销误操作。
- 学习统计：按日学习时长柱图、学习活动热力图、复习完成趋势及可筛选的原始记录列表。
- 设置：询问间隔、回答期限、复习间隔、本地数据位置、备份与恢复、存储模式和账户扩展状态。
- 笔记与复习条目悬停显示相关学习时间、上次复习时间、下次复习时间；未复习或无计划明确显示。
- 空数据展示引导，读取失败展示原因，不以示例数据冒充用户记录。

## 学习询问规则

1. 默认学习时间段为 60 分钟，设置范围为 5–240 分钟。修改设置从下一段开始生效。
2. 应用运行时自动计时；可以主动暂停与继续。应用关闭、暂停和系统休眠期间不新增学习时长。
3. 一个时间段结束后持久化为「待回答」，显示应用内提醒，并尝试使用 Windows 系统通知。
4. 默认回答期限 5 分钟，可设置为 1–30 分钟。用户填写学习摘要并可关联一份或多份笔记，提交后该段成为「已学习」。
5. 用户选择「没有学习」，或期限内没有回答，该段成为「未学习」。即使检测到文件改动，也不能自动将其计为已学习。
6. 提醒等待期间开始下一时间段，避免丢失运行时间；每段都有独立的起止时间、期限和状态。
7. 重启后恢复已保存记录并结算超时待回答记录，不把应用离线期间生成成新的未学习时间段。
8. 正常关闭保存未满一个时间段的活动累计时间；异常退出通过定期检查点恢复。重启时不计入退出至重启之间的时间。
9. 允许手动补记和更正记录，保留修改时间；统计与相关复习安排同步更新，并避免重复创建。
10. 统计中的学习时长是用户确认的时间段时长，不声称通过键盘或文件活动证明实际专注。

## Markdown 导入与变更历史

- 支持选择一个或多个 `.md` / `.markdown` 文件；读取 UTF-8 文本，兼容 UTF-8 BOM。无效编码或读取失败逐项报告。
- 导入保存原路径、标题、文件哈希和完整内容快照，同一路径重复导入不重复创建笔记。
- 原文件维持用户管理；应用不改写或删除原文件。
- 应用运行期间监测已导入文件，变动后防抖读取；以内容哈希去重，保存时间戳和版本快照。
- 对比版本展示新增与删除内容，提取变更涉及的 Markdown 标题及新增片段，为当前学习段生成建议摘要。
- 学习摘要、关联笔记和版本范围由用户确认，可编辑。首次导入仅建立基线，不自动算学习。
- 笔记没有改动时仍可手动记录阅读和学习。
- 文件丢失显示失联，保留历史快照；提供重新关联路径的入口。
- 应用未运行时的连续编辑无法全部追溯；下次启动比较最后快照与当前文件，标注为「离线期间变更」，不归入刚开始的学习段。
- 历史按内容快照保存于应用数据库；项目 Git 专门管理应用源代码，不在用户笔记目录初始化或提交 Git 仓库。
- 文件读取限制 10 MiB，超限显示原因；Markdown 阅读禁止执行原始 HTML 脚本，不自动请求外部图片或资源。

## 复习规则

- 首版采用可解释、可调的间隔复习计划，默认依次为学习确认后 1 天、再 3 天、7 天、14 天、30 天。
- 这是基于遗忘与间隔复习思路的产品默认值，不声称是每个人精确的记忆曲线。
- 每次确认的学习内容创建独立复习条目，关联学习记录与笔记版本；同一提交重复触发不得产生重复条目。
- 第一次到期时间为学习时间 + 第一个间隔；后续到期时间为实际复习完成时间 + 下一个间隔。
- 勾选完成保存复习事件并推进阶段；完成最后阶段后显示「本轮已完成」。
- 逾期条目保留到完成，不自动跳级。重复勾选同一个待复习事件不重复计数。
- 撤销最近一次复习恢复此前阶段和到期时间；已完成列表与统计随之更新。
- 调整默认复习间隔只影响新建计划，已有计划保存当时使用的间隔配置，保证可解释性。

## 数据与后续扩展

数据实体：设置、笔记、内容快照、学习时间段、学习与笔记关联、复习计划、复习事件。

每条业务记录使用稳定 ID、创建时间、修改时间及修订号，便于后续同步。设置包含 `local`、`cloud`、`hybrid` 三种模式的模型定义，但本地首版只允许启用 `local`。云端和双端选项清晰显示未配置状态，不能假装保存成功。

后续认证边界：微信授权开始、授权状态查询、会话恢复、退出。桌面不内置微信 AppSecret，令牌不以明文配置文件保存。首版账户区域说明微信登录尚未连接服务。

后续存储边界：同步配置、待同步操作、服务端修订、同步结果和冲突信息。云端模式应仅使用必要缓存，双端模式支持离线队列；真正同步、冲突解决和账号数据隔离将在后端阶段实现及测试。

本地首版支持一致性备份和恢复。恢复先验证备份格式与数据库完整性，并保留恢复前备份；不会通过删除用户资料目录完成恢复。

## 验收重点

1. 导入后重启仍能读取笔记、设置及历史。
2. 用可控时钟测试提醒、回答、拒绝、超时、跨日、暂停、休眠、重启与改间隔。
