# WW-StudyApp 0.6 同步与迁移指南

## 同步什么

StudyApp 始终保留完整本地资料库。同步目标只保存每份笔记的**最新 Markdown**，路径为 `StudyApp/notes/<UUID>.md`；标题保存在正文或本地笔记信息中，不作为路径。非 UUID 文件、其他格式和专用目录外的文件不参与同步。

学习记录、学习时长、复习计划、复习事件和完整版本历史不会通过 WebDAV / 文件夹同步。它们仍在本地 SQLite，通过「设置 → 导出备份」保存。远端新笔记或更新进入本地后形成离线快照，不自动记为学习。

应用不会传播删除，也不会清空同步目标。删除远端对象不会删除本地笔记；本地仍存在的笔记可能在下一次同步时重新上传。因此同步目录不能代替版本备份或删除管理工具。

## 主资料库的文件系统要求

托管笔记的新建、保存和恢复也依赖硬链接，**主资料库所在文件系统与同步目标都需满足各自要求**。建议把主资料库放在支持硬链接的本地 NTFS 目录；仅让 NAS 同步目录支持硬链接，并不能使不支持该操作的主资料库可写。应用会在记录托管写入意图前预检，不支持时拒绝该操作、保留编辑草稿，避免留下阻塞资料库打开的未完成写入。

## 文件夹或兼容 NAS

1. 准备一个已存在、具有读写权限的目录。选择绝对路径；NAS 应先通过 Windows 可访问的共享路径或挂载目录连接。
2. 在「设置 → 笔记文件同步」选择「文件夹 / NAS」，选择该目录，点击「保存全部设置」。应用使用其 `StudyApp/notes` 子目录和 `StudyApp/.sync.lock` 锁文件。
3. 点击「测试连接」，再使用一份无重要内容的笔记执行「立即同步」，核对另一资料库是否能接收并修改它。测试连接会创建或检查专用子目录、取得文件锁并列举文件，但不验证全部写入操作。
4. 有需要时开启自动同步，设置 5–1440 分钟的间隔并保存；应用运行时执行，关闭应用不执行定时任务。

该文件系统必须正确支持操作系统文件锁、硬链接和文件替换。初次创建笔记使用硬链接实现 create-only；不支持这些操作的 NAS / 挂载可能报告错误，即使列举测试成功也不能保证能写入。目录链接、Windows junction 和其他重解析点被拒绝。

锁只协调遵循该锁的 StudyApp 实例。替换现有对象前，应用将旧文件移入 `StudyApp/notes/.retained/<UUID>.original` 并复查内容；新内容先写入同目录的 `.pending` 暂存文件，再以 create-only 硬链接发布到目标。若目标又被第三方创建，应用拒绝覆盖，保留旧文件和暂存内容供恢复。保留目录不参与笔记列举，也不会自动清理，可能持续占用空间。

这一机制减少替换时丢失原文的风险，但普通文件系统不能为不遵守锁的第三方编辑器提供严格的原子比较与替换保证，也不能约束已有文件句柄继续原地写入。需要服务端严格处理并发写入时，使用正确实现 ETag 条件请求的 WebDAV；不要同时用另一同步工具改写专用目录。失败时请保留 `.retained` 内容供检查，不要把它当作可自动清空的缓存。

## HTTPS WebDAV

1. 使用已有 WebDAV 服务，确认目标父目录存在且账号有读取、创建目录和写入权限。地址填写最终 HTTPS 目录，例如 `https://dav.example.com/my-folder/`，不要将用户名或密码嵌入 URL，也不要附加查询参数或片段。
2. 在「设置 → 笔记文件同步」选择「WebDAV」，填写地址、用户名与密码或服务商应用密码，保存设置后测试连接，再执行同步。
3. 保存相同目标时，密码留空会继续使用已保护的凭据；更改目标或用户名时需要重新输入密码。更换 Windows 用户或设备后应重新配置。

客户端验证 TLS 证书，拒绝所有重定向，当前不读取系统 HTTP 代理。生产设置只允许 HTTPS；HTTP 仅能由显式测试构造器为数字回环地址开启，不能在产品设置中启用。

服务端需支持：

- `MKCOL` 创建或确认 `StudyApp/` 与 `StudyApp/notes/`；已有目录允许返回 405。
- `PROPFIND`，`Depth: 1`，返回有效 DAV multistatus 列表。
- `GET` 返回 UTF-8 Markdown；更新已有对象时需给出强 ETag，例如 `"revision-123"`。
- `PUT` 正确执行 `If-Match: <强 ETag>`，新建时执行 `If-None-Match: *`；条件不匹配返回 412。

弱 ETag（`W/"…"`）或没有 ETag 的对象可以被读取，但不能用它们覆盖远端已有对象。应用会报告错误并保留本地内容，不退回无条件写入。ETag 是否与内容一致、条件请求是否正确执行由服务端保证；兼容性需在实际服务上验证。

连接超时 5 秒，单请求总超时 20 秒；单份 Markdown 上限 10 MiB，列表 XML 上限 2 MiB，列举最多 10,000 个条目，一次同步读取的本地与远端内容合计上限 64 MiB。请求过大、无效 UTF-8、路径越界或不合法 UUID 会被拒绝。真实账号和 NAS 环境应自行完成往返验证；本地回环 fixture 通过不代表所有服务商兼容。

## 冲突和失败

应用比较本地、远端和上次成功同步的内容哈希。单方变化更新另一方；双方变化时，先将本地内容保存为独立托管冲突副本，再把远端内容写入原托管笔记。两份内容都保留，可以在笔记库比较后继续编辑。首次连接时，同一 UUID 两边不同也按冲突处理。

外部导入笔记仍是只读来源。其快照可以上传；远端变化拉回时创建托管副本，不能覆盖外部原文件。新出现的远端 UUID 笔记进入本地托管目录。

网络在独立后台线程运行。应用返回结果时再次检查本地版本；同步过程中又改动了本地内容，会提示再次同步，保留现有草稿与笔记。失败项不推进该笔记的同步基线；最近成功时间只在本轮没有错误时更新。关闭同步或切换目标不删除任何笔记文件。

## 凭据、备份与换电脑

当前配置由 `settings/manifest.json` 指向完整配置代。该代的 `sync.json` 保存目标地址、用户名和自动同步间隔，`credentials.json` 单独保存 **DPAPI 加密后的密码字节**。`sync-state.json` 保存同步基线、目标身份和最近成功时间，切换目标不会复用旧目标的基线。旧版 `sync-config.json` 在首次升级时导入并保留原件。密码绑定当前 Windows 用户；明文密码不进入 SQLite、应用备份、日志或发布包。

设置输入先作为草稿保留，点击「保存全部设置」才发布；离开设置页会提示保存或放弃。「恢复初始设置」将同步关闭作为默认草稿，保存后生效，已有远端文件保留。SQLite 恢复不会覆盖当前的独立分类设置。

建议迁移步骤：

1. 先完成需要的同步，在旧设备「导出备份」到一个新文件名。需要保留的草稿先保存为笔记。
2. 新设备选择目标资料库目录，再从 SQLite 备份恢复。托管笔记从备份快照生成在新库的 `notes/<UUID>.md`，学习记录与历史一并恢复。外部原始 Markdown 须另行复制并重新关联。
3. 重新配置同步目标和密码，再测试连接和同步。SQLite 备份不包含同步配置、基线、DPAPI 凭据或 `note-draft.json`。

仅连接同一远端、没有恢复 SQLite 备份，也能获取最新 Markdown，但不会恢复学习记录、复习进度和旧版本。不要将整个同步目录当作完整资料库；运行中的资料请用应用备份，避免只复制主数据库而遗漏 WAL。
