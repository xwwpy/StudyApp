# 云端与微信扩展契约（尚未实现）

StudyApp 0.1.0 的可用存储是本地 SQLite。`crates/studyapp-core/src/integration.rs` 只定义扩展接口，当前 `UnavailableServices` 对认证和同步操作返回明确错误；不会发起微信授权、上传笔记或假装同步成功。`StorageMode::{Local, Cloud, Hybrid}` 是后续模型，首版设置不能启用 Cloud/Hybrid。

## 当前边界

`AuthProvider` 包含 `begin_wechat_authorization`、`poll_authorization`、`restore_session`、`sign_out`。授权会话模型只有账号 ID 与过期时间，不包含真实令牌保存逻辑。`SyncProvider::synchronize(mode)` 返回上传/下载数量与实体修订冲突，尚无网络协议、队列、后端、账号隔离或冲突 UI。

本地实体以稳定 ID、UTC 时间及可变实体修订号作为后续基础；内容快照/复习事件有独立 ID。不能假定当前字段已经覆盖服务端同步需要的删除标记、幂等键或所有实体的修订元数据。

## 接入服务前必须实现的协议

1. 微信应用注册和桌面授权流程：由受信后端持有 AppSecret，使用一次性 state、防重放授权 ID、过期时间和显式取消。桌面轮询授权状态，后端交换微信 code，向桌面发放自己的短期会话。不能把微信 AppSecret 打进可执行文件。
2. 会话恢复、刷新、撤销及退出：令牌使用 Windows Credential Manager/DPAPI 等系统安全存储；本地设置文件只保存非敏感配置。当前没有令牌，因此不存在真实退出或账户切换行为。
3. 传输协议：使用 TLS、账号隔离、分页游标、协议版本、服务端修订号和客户端幂等键。定义增量上传/下载、删除标记、附件/快照大小限制、重试退避和网络失败状态；服务端独立验证所有数据。
4. 冲突规则：以实体 ID、预期服务端修订与本地修订检测冲突，展示冲突副本并由用户解决。笔记全文、学习摘要及复习事件不能靠无条件最后写入静默覆盖；操作重试不得重复创建复习事件。
5. 模式语义：Local 完全本地；Cloud 仅保留必要缓存且明确网络不可用行为；Hybrid 保留完整本地库和持久离线操作队列。只有获得服务端确认的操作才显示已同步。
6. 账户隔离与迁移：不同账户使用隔离库/缓存，退出保留或移除缓存由用户明确选择。导入已有本地数据必须有预览、去重、备份和可恢复失败路径，不能自动归入另一个账号。

上述条目是后续设计要求，不代表已有 API endpoint 或可用保证。真实接入验收需要测试过期授权、撤销会话、离线重试、重复请求、并发冲突、跨账户访问、备份恢复、协议迁移和服务端部署。云部署 CD、密钥管理及代码签名将在相应服务和证书就绪后配置。
