# App Performance and Data Views Implementation Plan

**Goal:** 消除设置/空间管理全量布局与 render 派生计算，提供可复用选色控件并验证全应用热路径。

**Architecture:** 后台报告与纯展示模型提供不可变数据，视图仅组合可见组件。缓存以明确的数据和布局依赖失效，操作仍回到权威数据层执行。

**Tech Stack:** Rust、GPUI Kit 0.7.3、GPUI 0.3.9、现有 worker/config/SQLite。

## 约束

- 禁止批量删除；不启动本机应用或操作用户桌面。Cargo 低优先级、2 jobs；原生验证仅 CI。
- 保留设置草稿/显式保存、资料库隔离、外部文件保护与更新器回滚。
- 不将缓存命中数等同于用户延迟；不因新优化削弱既有交互断言。

## 工作包

- [x] `settings_ui.rs`/`settings_components.rs`：可见快捷键及外观分段、确定尺寸视图缓存；无界面失效/离屏焦点/滚动范围回归。
- [ ] `storage_viewmodel.rs`/`storage_backend.rs`/`storage_ui.rs`：扫描后生成报告展示数据、可见副本行、动态草稿保护索引；千文件规模测试和原生嵌套滚动回归。
- [ ] 新颜色数据与控件模块、`settings_ui.rs`：色盘/HSL/精确值/自动适配、持久实体、原设置保存语义；纯解析及原生选择回归。
- [ ] 今日/复习/统计/笔记热路径审计：识别每帧扫描/排序/文件访问，抽取纯数据模型与失效规则，保留计时和跨天正确性。
- [ ] 统一验证：Clippy、完整无界面测试、独立原生性能对照与截图；修复实际失败、更新验证记录、提交推送与发行验收。

现有外观与快捷键变更先独立验收，后续工作包分别提交，避免将未验证的界面重构捆绑发布。
